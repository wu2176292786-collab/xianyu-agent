# 闲鱼运营 Agent：功能与操作运行手册

> 面向负责操作、排障或维护本项目的 Agent。
>
> 每次操作的完成标准：明确数据来源、外部写入风险、实际结果和下一步；所有真实外部写入须先得到人类明确授权。

## 0. 执行总则

每次处理任务先完成以下判断：

1. 在“自动化”读取读通道、写模式、急停状态和上次同步时间。
2. 区分操作是：只读同步、仅本地操作、可能写入闲鱼、还是同行公开页面采集。
3. 真实外部写入前，向人类说明对象、内容和影响并获得授权；查看本地状态、只读同步、测试无需重复确认。
4. 执行后以 toast、行动队列、最近动态和状态字段为验收依据，不因“按钮已点击”宣布成功。

```text
闲鱼 / 已打开的同行页面
        │
        ├─ 手动“刷新店铺数据 / 从平台同步” ──> 本地店铺状态（商品、曝光、会话）
        ├─ 采集端“加入研究” ───────────────> 本地研究状态（同行、观察点）
        └─────────────────────────────────> 运行 Agent / 自动巡检
                                                     │
                              建议进入行动队列，或按规则与写模式执行
```

- **同步**更新本地数据；**巡检**只使用本地已有数据，两者不能混淆。
- `运行 Agent` 和自动巡检不会拉取本店闲鱼商品、曝光或消息。
- 同行“监控”是独立流程：应用运行时按全局间隔使用本机浏览器打开到期同行商详。

## 1. 页面与功能地图

| 页面 | 作用 | 操作 | 外部影响 |
| --- | --- | --- | --- |
| `/` 总览 | 曝光、成交、待回复、在售、动态 | 刷新店铺数据；运行 Agent | 刷新只读；Agent 取决于写模式/规则 |
| `/queue` 行动队列 | 审批和追踪建议 | 通过、编辑后通过、忽略、重试 | 通过会按写模式执行 |
| `/inbox` 消息 | 查看会话、起草/发送回复 | 起草、编辑、发送 | 真实写入会发送私信 |
| `/listings` 商品 | 底价、热度、擦亮/改价/下架、看对手 | 确认底价、手动操作、看对手 | 写操作按写模式；看对手进入研究 |
| `/research` 选品研究 | 同行、证据、价格带、热度监控 | 任务、采集、监控、手动采集、文案 | 同行采集使用本机浏览器 |
| `/automations` 自动化 | 通道、安全、巡检、规则、店铺设置 | 配置、同步、急停、规则 | 真实写入改变后续写入目标 |
| `/automations/login` 账号与模型 | 登录态与 LLM | 导入/验证/清除 | 验证会访问相应外部服务 |

## 2. 店铺同步、曝光与 Agent

### 2.1 刷新店铺数据

**用途**：从当前读通道更新商品、在售状态、库存、商品热度、会话及已配置的订单数据。总览“近 7 天曝光”优先显示同步到的在售商品浏览数据。

**入口**：总览右上角 `刷新店铺数据`，或“自动化 → 通道与安全 → 从平台同步”。两者使用同一同步逻辑。

**真实账号步骤**：

1. 在“账号与模型”导入并验证闲鱼登录态。
2. 在“自动化”把读通道设为“真实闲鱼账号”。写模式可仍为“本地模拟”或“演练”。
3. 点击刷新，等待 `同步完成：…` toast。
4. 验收：总览显示“上次刷新 …”；最近动态含“已从真实闲鱼账号同步”；商品页显示同步结果。
5. 为新商品确认底价，之后才允许自动降价规则处理它。

**换号与空数据**：

- 导入新账号时会清空上一账号的商品、会话、订单，防止串号；必须再同步一次。
- “Agent 上次巡检”不代表同步完成；“上次同步：还没同步过”时先刷新。
- 同步为 0 件时保存 toast 和动态里的平台分组说明；先确认账号确有在售商品，再检查登录态、接口配置和映射。不要高频重复请求。

### 2.2 运行 Agent

手动运行与后台自动巡检走同一条路径：

1. 基于当前商品、消息、订单和规则生成候选动作；已配置模型时模型只能从候选中选择。
2. 更新会话意图标签。
3. 需要审批或被强制审批的动作进入行动队列。
4. 允许自动执行的动作经过急停、写模式、限流和失败熔断后执行。
5. 写入最近动态和巡检历史。

它**不会**同步本店数据、刷新同行搜索、绕过底价/审批/急停/限流。

| 写模式 | 运行 Agent 的结果 |
| --- | --- |
| 本地模拟 | 自动执行的动作只改本地状态 |
| 演练 | 记录本来会做的动作，不改业务字段、不写闲鱼 |
| 真实写入 | 自动执行的**回复**可能实际发到闲鱼；擦亮、改价、下架、发货的真实接口尚未接入，会明确失败 |

验收 toast 应列出“自动执行 / 待你审批 / 执行失败 / 被拦下”数量，或显示“暂时没有新建议”；结果必须能在行动队列和最近动态追溯。

## 3. 日常经营操作

### 3.1 行动队列

- `待审批`：核对理由后选择“通过并执行”“编辑后通过”或“忽略”。
- `执行失败`：读取失败原因后重试或编辑后通过；失败项不会静默删除。
- `已执行`：保留执行者、时间和演练标记。
- `已忽略`：仅忽略本轮建议，未来重新满足规则时可再次出现。
- 批量通过逐条执行；有失败时报告成功数和失败原因，不能报成全部成功。

### 3.2 消息

- 自动识别议价、规格咨询、催发货、问库存、售后等意图。
- “让 Agent 起草”先走规则模板；LLM 已配置时只做润色。编造数字、改掉还价或异常输出会回退模板。
- 发送前确认买家、商品、金额、库存与发货承诺。真实写入模式下，点击发送会真实发出私信。

### 3.3 商品与底价

- 商品页支持擦亮、改价、下架和“看对手”。
- 底价是红线：手动改价和规则降价都会再次校验，不得低于底价。
- 新同步商品的底价仅为保守估算并标记“待确认”；确认前自动降价必须跳过。
- 确认底价时金额必须合法且不高于当前挂牌价。
- “看对手”只更新选品研究；同行不会进入本店商品表，也不会自动影响本店价格。

## 4. 自动化配置

### 4.1 读写通道与安全

| 配置 | 值/范围 | 行为 |
| --- | --- | --- |
| 读通道 | 本地模拟数据 / 真实闲鱼账号 | 决定同步来源；切换真实读不会自动同步 |
| 写模式 | 本地模拟 / 演练 / 真实写入 | 决定写入目标；允许“读真实 + 写模拟” |
| 急停 | 开/关 | 停止所有写操作；不阻止只读同步 |
| 每分钟最多写 | 正整数 | 仅演练、真实写入生效 |
| 最小写入间隔 | 毫秒 | 仅演练、真实写入生效 |
| 连续失败急停阈值 | 正整数 | 达到后自动急停 |

风控会立即急停；登录失效、风控不盲目重试；急停或限流拦下的动作会在下一轮重新提议，而不是伪装成业务失败。

### 4.2 自动巡检

- 服务启动后每 30 秒检查一次是否到期；真正执行频率由店铺设置决定。
- 可开关，间隔为 **1–1440 分钟**，默认 15 分钟。
- 第一轮需人手动点击“运行 Agent”，后续才按间隔自动运行。
- 自动巡检同样不做本店同步。

### 4.3 内置规则

| 规则 | 默认参数 | 默认审批 | 作用 |
| --- | --- | --- | --- |
| 定时擦亮在售宝贝 | 24 小时；每轮 4 件 | 自动 | 选择久未擦亮的在售商品 |
| 滞销商品阶梯降价 | 上架 14 天；浏览 ≤260；5%；每轮 2 件 | 人工 | 低热度滞销商品降价，不低于底价 |
| 买家消息自动起草回复 | 每轮 6 条 | 人工 | 生成回复草稿/还价 |
| 超时未发货自动备单 | 宽限 24 小时 | 人工 | 生成备单建议 |
| 零库存自动下架 | 无 | 自动 | 避免零库存仍在售 |

每条规则可独立开关、修改参数和选择“人工审批/自动执行”。“自动执行”仍受当前写模式控制。

### 4.4 店铺设置和示例数据

| 字段 | 有效范围 | 用途 |
| --- | --- | --- |
| 店铺名 | 非空文本 | 展示和识别 |
| 议价最大让价 | 0–60% | 回复与议价保护 |
| 承诺发货时效 | 1–168 小时 | 超时备单阈值 |
| 回复签名 | 文本 | 回复尾部签名 |

- `清除示例数据`：清除示例商品、会话、订单、指标、示例研究任务，保留真实同步数据。
- `重置示例数据`：恢复初始演示状态，真实同步数据也会被覆盖。除非任务明确要求，先请求人类确认。

## 5. 真实账号与 LLM

### 5.1 闲鱼登录态

1. 在“账号与模型”导入浏览器导出的登录态。原文等同账号凭证，禁止写入文档、日志、对话或版本库。
2. 点击验证；成功后才切换真实读通道。
3. 手动同步一次，检查商品、会话和同步动态。
4. 换账号后，接受系统清空旧账号绑定数据，再同步新账号。

`XIANYU_COOKIE` 环境变量优先于 `.secrets/xianyu-login-state.json`。界面/日志只显示脱敏状态，绝不显示 cookie。

### 5.2 LLM

LLM 用于回复润色、同行筛选、研究问答、文案润色；未配置时规则巡检和模板回复仍可用。

操作：填写 OpenAI 兼容 `baseUrl`、`model`、密钥，保存后点击验证。模型输出须通过数值守卫；不得擅改价格、底价和还价数字。

## 6. 选品研究与热度监控

### 6.1 数据原则

- 研究任务保存关键词、必须包含/排除词、关联本店商品和同行观察。
- 只有“可比”同行进入价格带；“不同款”“存疑”不参与。人工结论优先。
- 观察只追加不覆盖；10 分钟内同一商品同一来源的重复观察合并；缺失字段保持缺失，不填 0。
- 趋势只比较**商品详情页**观察；搜索页卡片用于铺候选，不参与热度差值。
- 研究结论只展示证据，绝不自动进入行动队列或改本店商品。

### 6.2 采集

优先使用 `tools/xianyu-collector` Chrome 扩展：它仅读取当前页面已经发生的响应、内嵌 JSON、可见文字、图片和正文；搜索翻页通过点击页面“下一页”，不直接调用闲鱼接口。

1. 启动项目，在 `/research` 复制采集密钥。
2. Chrome 加载 `tools/xianyu-collector`，填写本机地址和密钥。
3. 正常打开闲鱼搜索页或商品详情页，选择研究任务并点击“加入研究”。
4. 在研究台确认导入结果、证据层（API / 内嵌 JSON / 可见文字）和缺失字段。

可手动导入快照。快照至少应含 `capturedAt`、`pageUrl`、`pageType`，并尽量携带 `api`、`hydration`、`dom` 或 `visibleText` 证据；禁止填造缺失的价格、想要或浏览。

### 6.3 全局监控间隔

- 在“热度监控”设置全局间隔，默认 **24 小时**，可设 **1–168 的整小时**。
- 只影响明确点为“监控”的可比同行；不影响本店商品同步频率。
- 新增监控或缩短间隔先经过每日安全容量校验；超预算时按提示增大间隔或减少监控数量。
- 到期监控优先由后台处理；同一间隔内已尝试的商品，手动采集也不会绕过冷却。
- 风控会暂停热度采集 6 小时；重新导入登录态可提前解除。遇到风控时停止重复点击。

## 7. 文件、环境变量与命令

### 7.1 本机状态

| 位置 | 内容 | 操作要求 |
| --- | --- | --- |
| `.data/state.json` | 店铺、规则、队列、研究、动态 | 通过 UI/Server Action 修改；测试前备份；不手工篡改生产状态 |
| `.secrets/xianyu-login-state.json` | 登录态与请求头 | 权限 600；绝不提交、打印或转发 |
| `.secrets/` 的模型配置 | LLM 密钥与配置 | 绝不提交、打印或转发 |
| `tools/xianyu-collector/` | Chrome 采集扩展 | 采集密钥不是平台凭证 |

### 7.2 环境变量（名称、用途与安全用法）

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 闲鱼凭证 | `XIANYU_COOKIE`、`XIANYU_USER_AGENT` | 覆盖本机登录态；`XIANYU_COOKIE` 优先级高，禁止打印或提交 |
| 闲鱼接口覆盖 | `XIANYU_API_LISTINGS`、`XIANYU_API_CONVERSATIONS`、`XIANYU_API_MESSAGES`、`XIANYU_API_ITEM_DETAIL`、`XIANYU_API_ORDERS`、`XIANYU_API_SEARCH` | 覆盖默认 MTOP 接口名；格式为 `mtop.xxx` 或 `mtop.xxx@版本`。卖出订单接口未确认时保持未配置，不用“买到的订单”代替 |
| LLM | `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_VISION_MODEL` | OpenAI 兼容模型配置；密钥只存本机 |
| LLM 高级 | `OPENAI_THINKING_HINTS`、`XIANYU_LLM_CONFIG_FILE` | 设为 `0` 关闭非标准思考提示；后者覆盖本机 LLM 配置文件位置 |
| 本地状态 | `XIANYU_STATE_FILE` | 覆盖 `.data/state.json` 路径；隔离测试必须指向临时文件 |
| 同行浏览器 | `XIANYU_HEAT_HEADED`、`XIANYU_HEAT_PROFILE` | 值 `1` 时显示热度采集浏览器；后者指定本机 Chrome 配置目录，含登录态，禁止提交 |
| 测试 | `BASE`、`CHROME_PATH` | E2E 的本机应用地址与 Chrome 可执行文件路径 |

## 8. 排障决策表

| 现象 | 先检查 | 正确处理 |
| --- | --- | --- |
| 店铺商品为 0 | 上次同步、读通道、登录态、最近动态 | 切真实读后手动同步；换号后必须再同步 |
| 曝光不更新 | 总览“上次刷新”、同步 toast | 点“刷新店铺数据”；不要用运行 Agent 刷曝光 |
| Agent 无建议 | 是否同步、规则开关、阈值 | 看动态和规则参数；不凭空创建建议 |
| 真实回复失败 | 写模式、急停、限流、登录态、风控 | 保留原因；风控时停止重试并处理登录/验证 |
| 自动降价未发生 | 底价确认、规则审批、热度 | 先确认底价，再检查规则和队列 |
| 同行无热度 | 是否商详采集、是否到期/暂停 | 从商详采集；保留“没抽到”，不填 0 |
| 监控间隔不能保存 | 1–168 整数、每日预算 | 增大间隔或减少监控商品 |
| 采集端连不上 | 服务、地址、采集密钥 | 启动服务，复制当前密钥，重填扩展 |

## 9. 变更验证

1. 先读取关联页面、Server Action、领域逻辑和已有测试，保持同步/巡检/写入/同行采集边界清晰。
2. 新增用户可见行为时，优先在 `tests/e2e.mjs` 加可观察 UI 测试；外部边界使用本地模拟或夹具。
3. 至少执行与改动匹配的 lint、相关 Vitest、`git diff --check`；可安全启动隔离服务时再执行 E2E。
4. 报告已验证项、未验证项及原因；不得把未运行的真实平台操作描述为成功。

## 10. 权威实现位置

本文档是操作手册，不替代代码；冲突时以实现为准并更新本文档。

- 同步、登录：`src/lib/adapters/actions.ts`、`src/lib/adapters/live/`
- 写入护栏：`src/lib/adapters/guard.ts`
- 巡检、规则、定时器：`src/lib/agent/tick.ts`、`engine.ts`、`scheduler.ts`
- 状态与字段：`src/lib/domain/types.ts`、`src/lib/store.ts`
- 同行采集、监控：`src/lib/research/`、`tools/xianyu-collector/`
- 可见入口：`src/app/`、`src/components/`
