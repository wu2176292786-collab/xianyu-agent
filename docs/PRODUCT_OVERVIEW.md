# 闲鱼运营 Agent：产品功能与技术栈说明

> 面向店主、试用者和协作开发者。日常操作请先读本文；由 Agent 执行操作、排障时请读[功能与操作运行手册](AGENT_OPERATIONS.md)。

## 1. 产品解决什么问题

闲鱼运营 Agent 是一套本地优先的卖家运营工作台。它把商品、买家消息、经营规则和同行观察汇总到一个界面，先给出有依据的建议，再由店主决定是否执行。

它关注四件事：

1. **本店经营**：同步在售商品、库存、商品浏览、会话及可用订单数据，展示曝光、成交、待回复和动态。
2. **可控运营**：按规则提出擦亮、降价、回复、备单、下架等建议；每个动作都有原因、状态和可追溯记录。
3. **价格保护**：商品底价是硬约束。手动与自动改价都不能低于底价；刚同步的商品必须先由人确认底价，自动降价才会处理。
4. **同行研究**：采集公开搜索页与商品详情页证据，观察价格带、文案和“想要”变化，帮助选品和写文案，但不会据此自动改价。

## 2. 一分钟理解：同步、巡检和写入是三件事

```text
闲鱼账号 / 已打开的同行页面
            │
     手动同步或采集（读取）
            ▼
     本地状态：商品、消息、指标、研究证据
            │
        运行 Agent / 自动巡检（分析）
            ▼
       建议与行动队列
            │
  人工审批或允许自动执行（受安全规则限制）
            ▼
     本地模拟、演练，或已授权的真实私信发送
```

- **刷新店铺数据**：从读通道更新本店商品、浏览/曝光和会话。总览的曝光要靠这个按钮更新。
- **运行 Agent**：只分析已同步到本地的数据，生成建议、更新消息意图并执行允许自动化的任务；它不会自行拉取商品或曝光。
- **执行动作**：是否真的影响闲鱼取决于写模式、人工审批、急停、限流与风控状态。

## 3. 功能地图

| 页面 | 面向店主的能力 | 关键说明 |
| --- | --- | --- |
| **总览** | 近 7 天曝光、成交、待回复、在售商品、动态；手动刷新店铺数据；运行 Agent | 刷新与运行 Agent 分开，避免把巡检误当同步 |
| **行动队列** | 审核、编辑后通过、忽略、重试每条建议 | 显示原因与执行结果；失败不会静默丢失 |
| **消息** | 查看会话、识别意图、生成并编辑回复 | 未配置模型时也能用规则模板；真实写入时发送会影响买家 |
| **商品** | 管理底价、库存和在售状态；发起擦亮、改价、下架；从单品进入“看对手” | 底价是不可突破的红线；新同步商品需确认底价 |
| **选品研究** | 建立研究任务、导入同行证据、分析价格带、记录热度变化、产出文案建议 | “想要”热度只比较多次商品详情页观察；结果不会自动改本店商品 |
| **自动化** | 设置巡检频率、规则开关、审批要求、读写通道、限流、急停与店铺设置 | 可做到“真实读取 + 本地模拟/演练写入” |
| **账号与模型** | 导入/验证闲鱼登录态，配置兼容 OpenAI 的模型 | 凭证仅保存在本机，页面只显示脱敏状态 |

## 4. 常用工作流

### 首次使用与每日查看

1. 启动服务，先使用本地示例数据熟悉页面。
2. 需要真实店铺数据时，在“账号与模型”导入并验证登录态，在“自动化”切换真实读通道。
3. 在总览点击“刷新店铺数据”，确认上次刷新时间、同步提示和商品数量。
4. 为新同步商品确认底价；未确认前自动降价会跳过它。
5. 点击“运行 Agent”，在行动队列核对建议后再决定执行。

### 同行研究与热度监控

1. 在“选品研究”创建任务，或从本店商品点“看对手”。
2. 用随项目提供的 Chrome 采集扩展，在你正常打开的闲鱼搜索页/商品详情页点击“加入研究”。
3. 只把“可比”的同行纳入价格带；不同款或存疑项保留但不参与计算。
4. 对需要持续观察的同行启用监控，设置全局间隔（默认 24 小时，1–168 个整小时）。
5. 查看证据和变化趋势，决定是否调整自己的商品策略；研究结论不会自动执行交易动作。

## 5. 自动化与安全边界

内置规则覆盖定时擦亮、滞销降价、消息回复草稿、超时未发货备单、零库存下架。每条规则都可单独设置开关、参数以及“人工审批/自动执行”。

| 写模式 | 会发生什么 |
| --- | --- |
| 本地模拟（默认） | 只更新本地状态，用于演示和开发 |
| 演练 | 记录本会执行的动作，不更改业务字段、不访问闲鱼写接口 |
| 真实写入 | 当前仅已接通私信回复；擦亮、改价、下架、发货缺少已验证的真实接口，会明确失败而非猜测执行 |

无论哪种模式，都遵循以下保护：急停、每分钟写入上限、最小写入间隔、连续失败熔断和平台风控自动暂停。模型只能在系统生成的候选建议中选择，并且回复中的金额、底价与还价数字会经过守卫校验。

**不做的事**：项目不会自动同步店铺数据、不会绕过审批/底价/急停，也不会把同行研究直接转成真实价格修改。登录态、Cookie、模型密钥和本地数据目录均被 Git 忽略，不能上传、转发或写进文档。

## 6. 技术栈

| 层次 | 技术 | 用途 |
| --- | --- | --- |
| Web 应用 | Next.js 16（App Router）、React 19、TypeScript | 服务端渲染页面、Server Actions 与类型安全的业务实现 |
| 界面 | Tailwind CSS 4、shadcn、Base UI、Lucide、Sonner | 响应式运营工作台、交互组件与提示消息 |
| Agent | `@earendil-works/pi-agent-core`、`pi-ai` | 将规则生成的候选动作交给模型筛选；无模型配置时回退到规则流程 |
| 本地状态 | JSON 状态文件（默认 `.data/state.json`） | 持久化店铺、规则、队列、动态和同行研究；适合单机本地运行 |
| 闲鱼读写适配 | MTOP H5 客户端、登录态校验、WebSocket IM | 读取真实店铺数据；已支持真实私信发送，其余真实写操作保守拒绝 |
| 浏览器采集 | Manifest V3 Chrome 扩展、`playwright-core` | 在用户已打开的页面中提取同行页面可见/已发生的数据，并用于隔离 E2E 浏览器控制 |
| 质量保障 | Vitest、ESLint、TypeScript、Node.js 22.12+ | 单元测试、静态检查与一致的本地运行环境 |

## 7. 代码结构

```text
src/app/              页面、Route Handler、Server Action
src/components/       运营工作台界面组件
src/lib/domain/       商品、规则、状态等领域模型
src/lib/agent/        巡检、建议生成、调度、LLM 与同步编排
src/lib/adapters/     本地模拟与真实闲鱼读写通道
src/lib/research/     同行采集、证据、比较、监控与文案分析
tools/xianyu-collector/ Chrome 同行采集扩展
tests/                Vitest 单元/集成测试与浏览器 E2E 脚本
docs/                 产品、操作手册和设计计划
```

## 8. 开发、验证与贡献

要求 Node.js **22.12+**。在仓库根目录运行：

```bash
npm install
npm run dev          # http://localhost:43117
npm run lint
npm run test
npm run typecheck
npm run build
```

提交改动前，至少运行与改动相关的 lint 与 Vitest，并确认 `git diff --check` 没有格式错误。浏览器 E2E 应使用独立的 `XIANYU_STATE_FILE` 和独立服务，避免碰到实际使用中的店铺状态。
