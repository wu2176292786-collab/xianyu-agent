# 选品研究 · 同行「想要」观察 · 执行计划

> 这一版解决的问题：**怎么在不爬站、不看图的前提下，看出同行的热度在怎么变。**
>
> 闲鱼没有给卖家看别人流量的入口。能拿到的公开代理指标是商品主页上的「想要」。
> 单次数字没有意义，有意义的是**同一件商品、多次回访、可回链**的差值。

## 1. 为什么是「想要」，为什么是回访

「想要」不是曝光，也不是浏览量，它更接近公开页上的意向计数。它的好处是：
商详页上人眼就能看到、不需要任何权限、也不需要猜。

关键约束来自现有架构，不是这一版新加的：

- 服务器**不拿卖家 cookie 去轮询别人的商详**。这和「写通道未接入」「后台巡检不碰真实账号」
  是同一条红线 —— 那种行为就是爬站，会把账号送进风控。
- 所以数据入口只能是：**人在正常浏览时发起选品研究**，Agent 只读当前页面上
  **已经画出来、且你点过授权**的内容。

由此推出一个必须接受的事实：**时间线的密度等于你回访的密度。**
监测因此被定义成「回访清单」，而不是爬虫。

## 2. 功能范围

### 2.1 做

| 模块 | 内容 |
| --- | --- |
| 研究任务 | 一次选品：名称、关键词、统一规格（必须含 / 必须不含）、对标本店哪件货、回访间隔 |
| 同行商品 | 以平台 `itemId` 为主键；标题、卖家、商详回链；**不进本店商品表** |
| 观察点 | 某时刻的「想要」、标价、交付方式、来源页类型；缺字段如实标记，绝不当 0 |
| 证据 | 每条观察带页面 URL、采集时间、抽取层级、命中的原文片段，可点回原页 |
| 想要趋势 | 只比较商详对商详的观察，算增量、间隔小时、日均增速 |
| 价格带 | 只用**规格对齐**的同行的最近一次观察，算最低 / 中位 / 最高 |
| 回访清单 | 上次观察超过回访间隔的同行，列出原链接，由你去打开 |
| 观察结论 | 由纯函数从观察点推出、每条挂证据；只在研究台展示，不进行动队列 |

### 2.2 不做

- 后台定时去拉同行商详（那是爬站）
- 让模型看图猜「想要」或流量（数字只认页面上抽出来的字段）
- 根据同行数据自动改你的标题、主图、价格（改善建议必须人工确认）
- 把同行商品混进 `listings`（规则引擎会拿别人的货去提案擦亮和降价）

## 3. 数据模型

新增一个独立的研究域，挂在 `AppState.research` 下：

```
ResearchTask      一次选品：关键词 + 统一规格 + 对标本店商品 + 回访间隔
RivalListing      同行商品：itemId 为主键，带一串观察
RivalObservation  一次观察：想要 / 标价 / 交付 / 来源 / 证据 / 缺失字段
```

三个设计决定值得记下来：

1. **同行和本店彻底分表。** `Listing` 上有底价、库存、擦亮时间，那是「我能操作的货」；
   同行只有「我能看到的数」。混在一起，规则引擎会去擦亮别人的商品。
2. **观察只追加，不覆盖。** 覆盖等于把历史抹掉，而这一版的全部价值就是历史差值。
3. **`wants` 是可选字段。** 读不到就是读不到，`0` 和「没读到」是两回事 ——
   把没读到记成 0，下一次读到 86 就会显示「涨了 86」。

## 4. 三层抽取

和真实读通道的候选路径同一思路：字段名只能靠抓包，而且会变，所以每层都给一组候选路径，
认不出就跳过并计数。

| 层 | 来源 | 稳定性 |
| --- | --- | --- |
| `api` | 你打开商详时，页面**自己已经拉回来**的响应 | 最稳。不新开请求，只读已经发生的响应 |
| `hydration` | 页面里内嵌的初始 JSON | 次之 |
| `dom` | 当前页面上可见的文字，如 `86人想要` | 兜底。命中的原文片段进证据，方便人点回去对 |

截图可以作为人眼核对的附件，但**不用来 OCR 出数字**。

## 5. 观察协议

- **只比较商详对商详。** 搜索卡片上的「想要」有时不展示、有时是另一套字段，
  和商详混算会造出假涨跌。搜索页的观察照样存，但不参与趋势计算。
- **短时去重。** 同一 `itemId`、同一来源、10 分钟内的重复观察只留一条，
  留下字段更完整的那条 —— 刷新页面不该变成一次「波动」。
- **对不齐就不比。** 规格对齐靠标题关键词 + 可见标签判定：
  命中「必须不含」判为不同款，命中全部「必须含」判为可比，其余一律**存疑**。
  只有「可比」的同行进价格带。拿日版当国行比，比不比更糟。
- **观察中断不当 0。** 商品下架、找不到「想要」、解析失败，都记成缺失。

## 6. 验收标准

- [ ] 同一 `itemId` 二次导入是追加观察，不覆盖旧证据
- [ ] 两次商详观察能算出增量、间隔小时和日均增速
- [ ] 搜索页观察不参与趋势计算
- [ ] 10 分钟内的重复观察只留一条，且留下字段更完整的那条
- [ ] 抽取不到「想要」时记为缺失，不写成 0
- [ ] 三层都能抽到数，并如实记录是哪一层给的
- [ ] 存疑和不同款的同行不进价格带
- [ ] 观察结论每条都挂得上证据，没有证据就不出结论
- [ ] 回访清单按上次观察时间和回访间隔算，不到期不出现
- [ ] 同行商品不出现在 `listings` 里，规则引擎不会对它们提案

## 7. 后续

- **采集端**：这一版先把契约做硬（快照 JSON → 本机解析）。采集可以是剪贴板 / 文件导入，
  以后换成扩展上的「加入研究」按钮，解析层不用改。
- **多模态**：真要接视觉模型，只加在「这两件能不能比」和「你的主图少了什么」上，
  不替换这条时间线，也不允许它产出数字。
