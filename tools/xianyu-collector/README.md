# 闲鱼选品研究采集端

一个 Chrome 扩展。在闲鱼的商品详情页或搜索结果页上点一下，把页面上已经显示出来的
公开数据投进本机应用的「选品研究」。搜索页会在当前标签里真点「下一页」，
页数跟应用里「每次搜索页数」走。

## 它做什么，不做什么

**做：**

- 旁听页面**自己已经发出并拿回来**的接口响应，顺手留一份；
- 读页面里内嵌的初始 JSON；
- 读当前页面上可见的文字（`86人想要`、`¥1,699`、`包邮`）；
- 读页面上已经画出来的商品图和描述，给研究台做素材和文案导出；
- 搜索页按你的一次点击，在当前标签里点「下一页」，连采应用里设定的页数；
- 把这三层分开放进快照，让应用如实标出每个数字是哪一层给的。

**不做：**

- **不自己去请求闲鱼接口。** 翻页是点页面上的按钮，让闲鱼自己拉下一页；
  扩展只旁听页面已经拿回来的响应，不预取、不轮询、不加请求；
- 不改请求、不加请求头、不碰 cookie；
- 不上传到任何第三方 —— 只 POST 到你自己填的那个 `localhost` 地址；
- 抽不到的字段不补猜的值，宁可让应用显示「没抽到」。

由此有一个必须接受的事实：**时间线的密度等于你回访的密度。** 想看出「想要」在涨，
就得隔一段时间再打开那个页面点一下。

## 装上

1. 应用先跑起来：在项目根目录 `npm run dev`；
2. 打开 <http://localhost:43117/research>，在页面底部的「浏览器采集端」里复制**采集密钥**；
3. Chrome 打开 `chrome://extensions`，右上角开「开发者模式」；
4. 点「加载已解压的扩展程序」，选这个 `tools/xianyu-collector` 目录；
5. 点一下扩展图标，填应用地址（默认 `http://localhost:43117`）和刚才复制的密钥，保存。

密钥是干什么的：`localhost` 对任何网页都是可达的，没有密钥的话你随便打开的某个网站
也能往你的研究里塞脏数据。它**不是**平台凭证 —— 既不能登录闲鱼，也动不了你的商品。
想换就在应用里点「换一把密钥」，然后回来重填。

## 用起来

1. 在闲鱼上正常浏览，打开一个同行的**商品详情页**；
2. 点扩展图标 → 选一个研究任务 → 「加入研究」。弹窗里也可以新建或删除任务；删除会连同这个任务下的商品一起移出。
3. 已经打开的 <http://localhost:43117/research> 会自己刷新。同一件商品再点一次就是**追加一条观察**，旧证据不会被覆盖。

搜索结果页也能点，会在当前标签里连点「下一页」，把应用里设定页数的卡片加进来 ——
适合开局批量铺同行。商品详情页仍然只采这一页。
但趋势只按**商详对商详**算：搜索卡片上的「想要」有时不展示、有时是另一套字段，
混算会造出假涨跌。所以铺完之后，要盯的那几件还是得进商详页点。

同一件商品、同一来源、10 分钟内点两次会合并成一条，留下字段更完整的那条 ——
刷新一下页面不该在时间线上变成一次「波动」。

## 顺带一个用途：找接口名

弹窗底部有「这一页调了哪些接口」。点开 → 「列出来」，它会报出当前页面**自己**发过的
闲鱼接口，带版本号和请求参数：

```
mtop.taobao.idlemessage.pc.session.sync@3.0
  data: {"fetchNum":20}
mtop.idle.web.xyh.item.list@1.0
  data: {"userId":"…","pageNumber":1,"pageSize":20}
```

这东西是用来补应用里还没配的接口的（比如「在售商品」「我卖出的订单」）。
以前只能开 DevTools 抓包，或者靠猜 —— 猜过一轮，14 个名字全是「接口不存在」。

用法：打开对应的页面（「我发布的 → 在售」、「我卖出的」），**刷新一下或点一下标签**，
再点「列出来」。它只报页面自己已经发过的请求，没发过就报不出来。

请求参数也一起报，是因为光有名字还不够 —— 每个接口要哪些必填参数还得再猜一轮，
而那一轮同样很贵（`userId` + `pageNumber` + `pageSize` 三个少一个都是同一个报错）。

## 排查

| 现象 | 原因 |
| --- | --- |
| 「页面上的采集脚本还没就绪」 | 扩展是在页面打开之后装的。先刷新闲鱼这一页，或在 `chrome://extensions` 里点扩展的「重新加载」，再点一次 |
| 「采集密钥不对」 | 应用里换过密钥了，回去重新复制 |
| 「连不上 http://localhost:43117」 | 开发服务器没跑，或者端口改了 |
| 导入成功但「没抽到想要」 | 这一页上确实没有「想要」字样。商详页往下滚一点再点 |
| 「地址里没有商品 id」 | 当前不是商品详情页 |

## 代码结构

```
manifest.json     MV3 声明：两个内容脚本 + 弹窗
interceptor.js    页面世界：旁听 fetch / XHR 的响应，读内嵌 JSON
collect.js        隔离世界：把三层拼成快照；在搜索页点「下一页」；报接口名
popup.js          选任务、按应用设定页数连采、POST 到本机应用；列接口名
```

`interceptor.js` 必须跑在页面世界（`world: "MAIN"`）—— 内容脚本活在隔离世界，
看不到页面的 `window.fetch`，也读不到页面内嵌的初始 JSON。
